Платформа: Android или iOS 

Подход: нативная или кроссплатформенная разработка — на выбор студента 

Инструменты: любая IDE, любые ИИ-модели и агенты 

Репозиторий: новый, отдельный от предыдущих лабораторных 

Цель работы 

Собрать полноценное мобильное приложение и доказать, что навык работы с ИИ-инструментами не привязан к одному языку. Смена языка здесь — обязательное условие, а не деталь реализации. 

Часть 1. Выбор темы 

Вариант А. Студент придумывает собственное приложение. Тема согласовывается с преподавателем до начала работы. 

Вариант Б. Если своей идеи нет — берётся конвертер валют из Лаб 3 и переносится на мобильную платформу с обязательным расширением функциональности (часть 3). 

Часть 2. Требование смены языка 

Приложение полностью пишется на языке программирования, отличном от того, что использовался в Лаб 3. Правило действует в обоих вариантах выбора темы, включая собственную идею. 

Переиспользование кода из Лаб 3 не допускается ни в каком виде — ни копированием, ни автоматическим переводом через ИИ с последующей правкой. Логика реализуется заново на новом языке.

Выбранный язык не должен совпадать с языком Лаб 3. Например, если Лаб 3 сделана на TypeScript, то React Native для Лаб 4 не подходит. 

Предупреждение по iOS. Сборка приложения под iOS требует компьютера с macOS и установленным Xcode. Без Mac реально доступен только Android. Кроссплатформенные фреймворки этого ограничения не снимают: разработка возможна на любой системе, но финальная сборка под iOS — только на macOS. Учитывайте это при выборе платформы. 

Часть 3. Функциональные требования 

Базовая функциональность — на усмотрение студента и определяется выбранной темой. 

Обязательное расширение по сравнению с Лаб 3: экраны сравнения и аналитики. 

Минимум два дополнительных экрана: 

Сравнение за неделю — динамика показателя за последние 7 дней 

Сравнение за месяц — динамика за последние 30 дней 

На каждом экране обязательны: 

График изменения показателя во времени 

Минимальное и максимальное значение за период 

Среднее значение за период 

Изменение за период в абсолютных единицах и в процентах 

Явное указание направления тенденции: рост, падение или отсутствие изменений 

Для варианта Б показатель — курс выбранной валютной пары. Для варианта А показатель определяется темой приложения и согласовывается с преподавателем. 

Источник исторических данных студент выбирает самостоятельно: API с историческими данными, множественные запросы к источнику по датам, накопление данных в локальной базе или комбинация подходов. Выбор и его ограничения описываются в отчёте. 

Учитывайте: если данные накапливаются только локально с момента установки приложения, к моменту сдачи месячного графика может не оказаться. Продумайте это заранее. 

Часть 4. Требования, унаследованные из Лаб 3 

Работа офлайн. Приложение не падает при отсутствии сети. Последние успешно полученные данные кэшируются локально и переживают перезапуск приложения. При работе с кэшем пользователю явно показывается дата актуальности данных. 

Обработка ошибок. Недоступность источника, пустой ответ, некорректные данные — обрабатываются с понятным сообщением, без аварийного завершения. 

Unit-тесты. Обязательное покрытие: разбор ответа источника данных, расчёт статистики для экранов сравнения (минимум, максимум, среднее, процентное изменение), поведение при пустом наборе данных, валидация пользовательского ввода. Тесты запускаются одной командой, описанной в README. 

Git и ветки. Отдельная ветка на каждый этап работы. Осмысленные сообщения коммитов. История должна отражать процесс — один коммит на всю лабораторную не принимается. Слияние в основную ветку только через Pull Request.

Часть 5. Сдача и демонстрация 

Приложение демонстрируется запущенным: на физическом устройстве или в эмуляторе. Скриншотов и видеозаписи недостаточно. 

При защите преподаватель может попросить: 

Перевести устройство в режим полёта и показать поведение приложения 

Объяснить любой фрагмент сгенерированного кода 

Показать историю веток и Pull Request 

Часть 6. Критерии приёмки 

Новый отдельный репозиторий 

Язык реализации отличается от языка Лаб 3 

Код Лаб 3 не переиспользован 

Приложение запускается на устройстве или в эмуляторе 

Присутствуют экраны сравнения за неделю и за месяц 

На экранах сравнения есть график, минимум, максимум, среднее, изменение в процентах и указание тенденции 

Отсутствие сети не роняет приложение, кэш работает после перезапуска 

Unit-тесты присутствуют и проходят 

История git отражает процесс, слияние через Pull Request
